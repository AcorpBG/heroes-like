# Native RMG Core Drift Against H3MapEd Recovery Ledger

Document role: focused drift audit for `src/gdextension/src/rmg_native_core.cpp` and `src/gdextension/include/rmg_native_core.hpp` against `docs/h3maped-rmg-end-to-end-behavior.md`.

This is an audit/marking document only. It does not claim implementation progress. It deliberately compares the active `rmg_native_core` adapter surface to the recovered H3MapEd end-to-end behavior, not to final-map counts, package reports, or prior proxy code.

## Verdict

`rmg_native_core` is not a native port of the recovered H3MapEd RMG chain. It is a no-Godot blocked wrapper around a partial support path:

- controlled-case parsing;
- optional setup/template catalog feed;
- coordinate/source-node/boundary/span-fill/TerrainPlacement support call into `h3maped_rmg_core`;
- a partial recovered generator-object private-state carrier with generated-cell buffer `+0x14`, dimensions `+0x18/+0x1c/+0x20`, accepted candidate-vector count, and source-owner/player-slot counts;
- a partial object source-record catalog mirror with corrected metadata `+0x08` wrapper-bucket lanes;
- blocked JSON emission.

That is useful as a fail-closed diagnostic wrapper, but it drifts from the recovery ledger anywhere a caller treats it as an entrypoint-to-writeout native generator.

Current audit pass: 2026-06-20 at native head `5fd57b65`. The pass compares the active `src/gdextension/src/rmg_native_core.cpp`, `src/gdextension/include/rmg_native_core.hpp`, and the shared `h3maped_rmg_core` surfaces they call against `docs/h3maped-rmg-end-to-end-behavior.md`. One important source-backed correction is included from the recovered object metadata artifact because the ledger only names the wrapper/selector functions at a high level: H3MapEd routes loaded object wrappers by object metadata entry `+0x08` bucket index, not by copied source-record type `+0x1c`.

This pass found no additional native-owned source-order phases beyond the already marked partial setup/catalog/coordinate/boundary/terrain/generator-object/object-catalog support surfaces. Every recovered ledger spine step and every private-state/writeout section is marked below as either blocking drift, closed misleading-surface drift, source-backed exclusion, or scope limit.

## Current Native Code Anchors

The active native adapter has these source anchors:

- `ControlledCase` is a synthetic no-Godot CLI schema, not the H3MapEd UI/generator object entrypoint (`src/gdextension/include/rmg_native_core.hpp:10-25`).
- `SharedRuntimeChainInput` preserves some recovered setup/template/player-slot/runtime-zone/link fields, but it is a summary handoff, not the full generator object layout (`src/gdextension/include/rmg_native_core.hpp:190-230`).
- `RecoveredOwnerGridPayload` carries partial coordinate/terrain/generated-cell/generator-object/object-catalog report data, not final map payload authority (`src/gdextension/include/rmg_native_core.hpp:332-427`).
- Generated-cell record export now comes from a generator-object-style private-state carrier: generated-cell buffer `+0x14`, dimensions `+0x18/+0x1c/+0x20`, then `0x49a072 -> 0x499ea3` reset shape, owner/terrain overlays, and the recovered `0x4a5767` full-grid projection reset. It still explicitly labels itself not comparable to pre-`0x4a4c8e` private state because the relation scan, propagation, object-reference, and object/materialization callers remain unported (`src/gdextension/src/rmg_native_core.cpp:196-247`, `src/gdextension/src/rmg_native_core.cpp:1175-1208`, `src/gdextension/src/rmg_native_core.cpp:1640-1763`).
- The only object identity surface in this file is catalog/bucket/resolver/selector reporting; it stops at `0x49da08`, `0x49db76`, sampled `0x4af785`, `0x4af89f`, and sampled `0x4a9e40`, with live `0x4af785` wiring into descriptor/object materialization, `0x4903e8`, selected copied records, and object materialization still named as blockers (`src/gdextension/src/rmg_native_core.cpp:940-977`).
- `resolved_shared_runtime_chain_input()` can call setup/template helper surfaces when a controlled case supplies `setup_object_0x44`, but it does not own the continuous `0x4602c1 -> 0x4adfe1 -> 0x49ecf2 -> 0x49f0cd -> 0x4ac552` private-state chain (`src/gdextension/src/rmg_native_core.cpp:1534-1637`).
- `build_recovered_owner_grid_payload()` calls only the shared coordinate/source-node/boundary/span-fill/terrain support path, then records that generated-cell private state is not comparable (`src/gdextension/src/rmg_native_core.cpp:1640-1763`).
- `case_shared_h3maped_state_chain_blocked_json()` hard-blocks output: no generation output, no `.amap`, no runtime generation, no end-to-end parity (`src/gdextension/src/rmg_native_core.cpp:1777-1818`).

## Short Form

The native wrapper currently reaches only this subset:

`controlled case -> optional 0x49ecf2 -> optional recovered catalog 0x4ac552 helper with accepted candidate-container records and source-owner/player-slot buffers -> 0x4a218c/0x4a1f3b/0x4a19ed -> 0x4a3a03/0x4cca55 -> 0x4a2777/0x4a325d/0x4a3710 -> 0x49b53d/0x4a3f27/TerrainPlacement support -> partial generator-object private-state carrier with generated-cell buffer +0x14, known candidate/player-slot counts, and recovered 0x4a5767 full-grid projection reset -> partial object catalog mirror with metadata +0x08 wrapper buckets and sampled 0x4af785/0x4af89f/0x4a9e40 resolver/selector mechanics -> blocked JSON`.

- H3MapEd UI/entrypoint/private generator object setup;

- complete candidate/source setup containers;
- live `0x4af785` resolver wiring into descriptor/object materialization, `0x4903e8` descriptor joins, selected copied source records carried through object selection, and object-vector materialization;
- fully mutated stride-`0x30` generated-cell records beyond the generator-object reset/owner/terrain/`0x4a5767` full-grid reset partial record carrier;
- relation/scoring/object caller order;
- town/castle placement;
