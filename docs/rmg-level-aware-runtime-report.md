# RMG level-aware runtime correction

Completed implementation child, 2026-09-05; not full-goal or native-parity certification. Source chain: `project.md` → `bugfix-rmg-level-aware-runtime-20260905` in `PLAN.md` / `ops/progress.json` → `rmg-audit-corrections-requirements.md` and the completed source audit → runtime owners below → focused evidence.

## Root cause and runtime changes

The native start contract already retained the correct underground coordinates. Adoption and gameplay subsequently flattened positions, queried only surface terrain, merged same-XY objects from both layers and used one fog payload. This is an Aurelion runtime/adoption defect, not evidence to change recovered H3MapEd generation.

`OverworldLevelRules.gd` defines spatial levels separately from hero experience rank. The legacy map remains surface terrain; underground rows derive from immutable package layers. Legacy spatial records without a level remain on surface zero. Surface records keep their old compact representation.

`NativeRandomMapPackageSessionBridge.gd` keeps starting levels and performs supplemental support searches/reservations on each town's own layer. `OverworldRules.gd` uses per-layer occupancy and spatial lookup indexes, preserves movement levels, isolates interactions and cached destination descriptors, and maintains permanent exploration per layer with a current-hero compatibility mirror. Nearest-town support, reserve deliveries, threats and stationing cannot cross layers through a two-coordinate comparison.

The map, minimap and shell select terrain, roads, objects, heroes and fog by viewed layer. A compact accessible Surface/Underground control changes only the camera layer; remote viewing cannot move the hero. The footer offers Show Active Hero on the other layer. Hero and town roster selection focus the correct level.

Enemy path contexts, occupancy, staging, scouting/memory, saved targets, reinforcement/regrouping, local interception and spawn points retain their layer. Exploration target identities distinguish matching coordinates on different layers. Hero experience ranks are not interpreted as map levels. Local authored transit queries are layer-specific; native paired transit remains a separate unfinished child.

Battle payloads/normalization and scenario town-stationing preserve spatial levels and entrance identity. The live battle save test also exposed a pre-existing normalization omission: battle `army_slot_index` was lost on reload, changing surviving army formation. Valid slot indices now survive normalization; no combat statistics or RNG rules changed.
