## Generated Cell Layout

Recovered layout:

- Stride: `0x30`.
- `+0x04/+0x08`: object-reference dword vector begin/end observed by `0x49e1bf`.
- `+0x10/+0x14/+0x18`: projection/local coordinate triple written by `0x4a5767` and read by `0x4a606b`.
- `+0x1c`: projection/local word gate forced by `0x4a5767` and thresholded by `0x4a746b`.
- `+0x20`: score/owner word consumed by the `0x4a4c8e` family.
- `+0x24`: terrain/art word; low 6 bits are terrain id.
- `+0x28`: generated-cell bit-state word.
- `+0x2b`: validity/private byte; bit `0x02` is tested by `0x49a1d8`, and bit `0x04` is cleared by `0x4a5a23` for nearby same-owner cells.
- `+0x2c`: private flags; bit `0x01` suppresses `0x49a932` and `0x49aa63`.

The grid wrapper seen by `0x49a072` uses:

- `+0x08`: generated-cell buffer.
- `+0x0c`: width.
- `+0x10`: height.
- `+0x14`: level count.

The generator object seen by `0x4a4c8e` / `0x4a8c15` uses:

- `+0x14`: generated-cell buffer.
- `+0x18`: width.
- `+0x1c`: height.
- `+0x20`: level count.
- `+0xc8/+0xcc`: index-keyed pointer vector begin/end used by `0x4a5e73`.
- `+0xd8/+0xdc`: index-keyed pointer vector begin/end used by `0x4a5e73`.
- `+0xec4`: object record vector anchor observed by `0x4a54a7`.
- `+0xecc`: object record vector insertion/end pointer observed by `0x4a54a7`.
- `+0xed4`: optional handler pointer used by `0x49eb8d` for invalid bit26 candidate cells; vtable slot `+0x08` is called with the per-cell budget.
- `+0xed8`: source handler pointer assigned by `0x4af463` from its stack `+0x08` argument and used by `0x4af910`.
- `+0xedc`: 16-byte vector/anchor initialized by `0x4af463`.
- `+0xeec`: 16-byte pending-entry vector anchor initialized by `0x4af463`; `0x4af463` appends 8-byte `(handler key, object record)` entries and `0x4af910` erases accepted entries through `0x4afaea`.
- `+0xef0/+0xef4`: pending-entry vector begin/end read by `0x4af910`.
- `+0xf5c`: current endpoint/index cursor used and advanced by `0x4a5e73`, `0x4adb72`, and `0x4add76`; observed constructor/candidate setup does not initialize it directly.
- `+0x10e4`: relation/vector begin pointer consumed after `0x4a4c8e`.
- `+0x10e8`: relation/vector end pointer consumed after `0x4a4c8e`.
- `+0x10d4/+0x10d8`: candidate-container pointer vector begin/end built by `0x49f0cd` and consumed by `0x4ac552` before selected relation owners are adopted into `+0x10e4/+0x10e8`.
- `+0x1104/+0x1108`: byte-state vector begin/end sized from the `+0xd8/+0xdc` pointer-vector count by `0x49f95a`, then used by `0x4a5e73` to mark and advance the index cursor.
- `+0x1110`: descriptor-type counter table indexed by descriptor `+0x1c` in `0x4a54a7`.

## Recovered Functions

`0x499e65` constructs one generated-cell record and calls `0x499ea3`.

`0x49a072` resets the full generated-cell grid. It reads the wrapper buffer and dimensions, then calls `0x499ea3` for `width * height * level_count` records while advancing by `0x30`.

`0x499ea3` is the generated-cell initializer. It:

- clears `cell+0x2c` bit `0`;
- writes `cell+0x10 = 0xffffffff`;
- writes `cell+0x1c = 0x7fbc7fbc`;
- writes `cell+0x20 = 0xffff7fbc`;
- writes `cell+0x24 = (old & 0xc0000548) | 0x00000548`;
- writes `cell+0x28 = (old & 0x01000000) | 0x0a000000`.

So the initializer intentionally sets bit25 and bit27. The pre-`0x4a4c8e` H3MapEd state having only 407 bit27 cells is caused by later mutation phases, not by a different initializer.

`0x49a1d8` is a generated-cell validity predicate. It returns true only when:

- `cell+0x2b & 0x02` is non-zero;
- `(cell+0x24 & 0x3f) != 9`.

`0x49acf6` writes terrain/art and private per-cell flag bits. It:

- writes `cell+0x24 = (old & 0xffffc000) | (terrain_arg & 0x3f) | ((arg2 & 0xff) << 6)`;
- writes `cell+0x28` by clearing bit `15` and OR-ing `((arg3 & 1) | ((arg4 & 1) << 1)) << 15`;
- is called by `0x49ce64` after `0x49a072` reset in a full-grid stride-`0x30` loop.

`0x4a59e2` packs generated-cell projection/local fields. It is directly called only by `0x4a5767`. It receives the generated cell in `ecx` and three stack arguments:

- stack `+0x04` becomes the high word of `cell+0x1c`, while the existing low word is preserved;
- stack `+0x08` is masked to three bits, shifted into `cell+0x28` bits `12..14`, and the previous bits `12..14` are cleared first;
- stack `+0x0c` becomes byte3 of `cell+0x20`, while the lower 24 bits are preserved.

`0x49a85d` is a clipped 3x3 bit27 neighborhood stamp. It uses the grid wrapper layout `+0x08` cell buffer, `+0x0c` width, `+0x10` height. For coordinate `(x, y, level)`, it computes:

`cell = grid+0x08 + 0x30 * (((level * height) + y) * width + x)`.

It calls `0x49a932(true)` for the center cell and then calls `0x49a932(true)` for every cell in the clipped rectangle `[x - 1, x + 2) x [y - 1, y + 2)` on that level. This intentionally revisits the center cell.

`0x49a932` is a bit27 writer guarded by `cell+0x2c bit0`:

- false argument clears bit27;
- true argument sets bit27 and clears bit26.

`0x49aa63` is a bit26 writer guarded by `cell+0x2c bit0`:

- false argument clears bit26;
- true argument sets bit26 and clears bit27.

`0x49a962` is the related bit26/bit27 neighborhood helper. It uses the same coordinate formula as `0x49a85d`. It calls `0x49aa63(true)` for the center cell, then scans the clipped 3x3 neighborhood. For each neighbor, it calls `0x49a932(false)` only when:

- bit22 in `cell+0x28` is clear;
- `0x49a1d8(cell)` returns true;
- terrain id `(cell+0x24 & 0x3f)` is not `8`.

`0x49abd6` stamps object/vector footprints into generated-cell state. Runtime seed-58 trace shows five calls before `0x4a8c15`, all returning through `0x4a54d6`. The internal `0x49ac6b` call-site trace records exactly five body-cell writes through `0x49a932(true)`, at generated-cell flats `184`, `666`, `604`, `975`, and `1059`. These five flats are the seed-58 pre-`0x4a4c8e` bit22 cells and also retain bit27.

`0x499ee8` removes an object record reference from a generated cell. Static instruction recovery from `.artifacts/rmg_recovery/ghidra_499ee8_cell_reference_removal_dump/` shows it receives the generated cell in `ecx` and the object record pointer on the stack, scans the cell object-reference vector at `cell+0x04/+0x08` for that record pointer, and calls `0x4cce95` with the matching vector position. After removal, when the object-reference vector is empty, it clears generated-cell bit22 and sets bit25 in `cell+0x28`. It also resets the low word of `cell+0x20` to `0x7fbc` while preserving the high word. It is called by `0x4add76` and `0x4af910`.

`0x4802ac` constructs the concrete source handler passed into `0x4afa99` from its only two call sites in `0x484d9f`. Static instruction recovery from `.artifacts/rmg_recovery/ghidra_4802ac_source_handler_constructor_dump/` shows it receives the destination handler object in `ecx`, a source pointer at stack `+0x04`, a secondary source/policy pointer at stack `+0x08`, and a mode byte at stack `+0x0c`. It calls `0x42a1ec(source)` twice, stores the second result at handler `+0x04` and the first result at handler `+0x08`, stores the source pointer at handler `+0x0c`, stores the secondary pointer at handler `+0x10`, stores the mode byte at handler `+0x14`, and installs vtable `0x53eafc` at handler `+0x00`.

The `0x53eafc` source-handler vtable is resolved through the constructor and Ghidra data-reference verifier `.artifacts/rmg_recovery/source_handler_53eafc_vtable_ghidra_summary_20260610.json`, generated by `tools/rmg_h3maped_53eafc_vtable_ghidra_summary.py`. The verifier uses Ghidra reference files only: `0x4802ac` installs vtable `0x53eafc`, and slots `+0x00..+0x20` have data references from `0x53eafc..0x53eb1c`. The slots used by `0x4af463`/`0x4af910` are:

- `+0x00 -> 0x4802ea`: initializes the stream key through `0x42a28e(source, mode != 0)` and `0x42b690`; returns false when the sentinel at `0x535228` is reached, otherwise writes the key to the output pointer and returns true.
- `+0x04 -> 0x48031b`: advances an existing stream key through `0x42b6a7`; returns false on the same sentinel, otherwise updates the key in place and returns true.
- `+0x08 -> 0x480352`: maps a stream key through `0x42b62a`, returns `mapped+0x04+0x0c`; this is the pointer passed from `0x4af463` into `0x4af785`.
- `+0x0c -> 0x48037b`: maps a stream key through `0x42b63b` and copies two dwords from that mapped record to the output pointer.
- `+0x10 -> 0x4803b6`: maps x/y through `0x42b60f`, returns the low nibble of the mapped record's first dword; `0x4af463` feeds this value to `0x49acf6`.
- `+0x14 -> 0x4803e2`: calls `0x43c5c4(secondary pointer, x, y, mode)` and returns true only when that result equals `1`.
- `+0x18 -> 0x4803ff`: calls `0x43c5c4(secondary pointer, x, y, mode)` and returns true only when that result equals `2`.
- `+0x1c -> 0x48041d`: source-side helper slot present in the table; not consumed by the recovered `0x4af463` / `0x4af910` path.
- `+0x20 -> 0x48047c`: calls `0x429ea3(source, mode, key)` with the queued handler key from `0x4af910`.

Focused dumps at `.artifacts/rmg_recovery/ghidra_53eafc_source_handler_helpers_dump/` and `.artifacts/rmg_recovery/ghidra_53eafc_source_handler_nested_helpers_dump/` recover the lower helper chain used by those slots:

- `0x42a1ec` reads the source header chain and indexes global table `0x535214`; `0x42a1e6` and `0x42a1f9` are sibling source-header accessors for the source header `+0x08` dword and `+0x10` byte.
- `0x42a28e(source, mode_index)` selects the mode-specific stream/table pointer from the source object through the source vtable/data `+0x1c` chain.
- `0x42b690` returns the first stream key from the selected table, and `0x42b6a7` advances by using the current key as an index into 5-dword stream records. The sentinel `0x535228` remains the end marker checked by the concrete vtable slots.
- `0x42b62a` delegates to `0x42a83a`; `0x42a83a` maps a stream key into a 5-dword record slot and returns `slot+0x10 -> pointer+0x08` when that pointer exists. This is the object/descriptor source that `0x480352` offsets before handing it to `0x4af785`.
- `0x42b63b` maps a stream key into the same 5-dword record family and copies the two dwords at slot `+0x08/+0x0c` to the caller output.
- `0x42b60f` delegates x/y lookups to `0x42a4d0`; `0x42a4d0` maps two coordinate arguments into a 6x6 chunked grid and returns a 12-byte per-tile record pointer. `0x4803b6` returns the low nibble of that record's first dword.
- `0x43c5c4` maps x/y/mode into a 12x12 chunked, packed 2-bit tile-class grid. The class result is compared against `1` and `2` by vtable slots `+0x14` and `+0x18`.
- `0x429ea3` removes a queued key from the source-side mode-selected mutable vector through `0x42034a`, cloning first through `0x432c27` when the source holder is shared. `0x42034a` may clone the selected vector through `0x432d56` and then erase through `0x42ab68`.
- Focused dumps at `.artifacts/rmg_recovery/ghidra_53eafc_source_handler_erase_helpers_dump/`, `.artifacts/rmg_recovery/ghidra_53eafc_source_handler_erase_callees_dump/`, and `.artifacts/rmg_recovery/ghidra_42b127_source_edge_helper_callees_dump/` recover that lower cleanup path. `0x432d56` allocates a 0x18-byte clone, initializes refcount `1`, copies the old holder payload through `0x42a51c`, decrements the old holder refcount, and stores the clone in the caller pointer. `0x42a51c` copies five dwords from the source holder and increments the refcounts pointed to by copied fields `+0x04` and `+0x0c`. `0x42ab68(container, key)` copy-on-write clones `container+0x0c` when shared, unlinks `key` from a 5-dword record chain by patching the neighboring records' first two dwords, pushes the removed key onto the container free list headed at `container+0x08`, updates `container+0x10`, and calls `0x42abe8` to release the removed record's auxiliary pointer. `0x42abe8` decrements the refcount at the record auxiliary pointer and destroys/frees it through `0x436cd1`/`0x5044da` when the refcount reaches zero. `0x42b127(container, key)` is the non-head edge-maintenance helper: it derives the removed record's two-dword payload from the 5-dword key record, builds a clipped scan rectangle through `0x42b432`, tests descriptor masks through `0x42ccc6` and `0x42af44`, removes the key from nested 8-byte and 4-byte vectors through `0x4afaea`/`0x4cce95`, and releases now-empty nested holders through `0x42b2cc`.
