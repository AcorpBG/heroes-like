# Idle in-betweens (RIFE)

`tools/idle_inbetweens.py` makes smoother creature idle loops. It adds frames generated by a neural frame interpolator (RIFE v4.26) between a unit's accepted idle frames. The accepted frames stay unchanged as every (n + 1)-th frame, so all of the painted motion is kept, and the loop plays at about 60 ms per frame instead of 120–250 ms.

Owner direction, 2026-10-11, after comparing approaches on real units:
- Rigging the paintings (Skeleton2D-style bone warps) was rejected: the motion was much smaller than in the paintings, and a rig took 2–3 minutes of authoring per unit.
- Optical-flow blending (OpenCV DIS and Farneback) ghosted on large motions of thin parts such as spears, wings and ballista arms.
- RIFE kept the motion of the paintings and was accepted as the workflow.

The tool only writes candidates; nothing in the game changes (see "Not yet in the game").

## Running it

```text
python tools/idle_inbetweens.py UNIT_ID [UNIT_ID ...] --out DIR [--review]
python tools/idle_inbetweens.py --all --out DIR
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--inbetweens N` | `auto` | Frames added per pair. `auto` aims at about 60 ms per frame at the idle's own timing: `round(frame_msec / 60) - 1`. |
| `--coarse auto\|always\|never` | `auto` | When to use the coarse flow pass (see "Method"). `auto` retries smeared pairs with it. |
| `--archive-dir DIR` | `$HEROES_SOURCE_ARCHIVE` | Source-art snapshot, for source images that are not restored in the checkout. |
| `--weights FILE` | `$HEROES_RIFE_WEIGHTS`, else `~/.cache/heroes-like/rife_v4.26.safetensors` | The model weights. |
| `--device` | `cuda` if available, else `cpu` | The torch device. |
| `--review` | off | Also writes `review.mp4`. It shows the current idle above the new loop, at game size and zoomed 2x, on a battlefield. Needs `ffmpeg` on PATH. |

Source images are read from the checkout if they are restored there. Otherwise they are read straight from the source-art archive (`N:/heroes-like-archives/source-art/2026-10-03-ccc0d334` on the owner's Windows machine; see `docs/source-material-storage-map.md`), and every payload is checked against the archive's SHA-256 manifest. Nothing is extracted into the repository.

The tool writes one folder per unit under `DIR/<unit_id>/`:

| File | Contents |
| --- | --- |
| `idle_frames.png` | All frames aligned on their ground anchor, at source resolution. |
| `idle_recipe.json` | A `tools/pack_unit_pose_art` recipe for that sheet. |
| `idle_runtime.png` | The packed game cells, at the unit's frame size, ground margin and scale. |
| `report.json` | Source recipe, frame counts, the new `frame_msec`, timings, the weights' SHA-256, and the smear ratio of every in-between. |
| `flagged.jpg` | Each flagged pair with its in-betweens at 2x. Written only when a pair is flagged. |
| `review.mp4` | The review video. Written only with `--review`. |

`DIR/summary.json` lists every unit in the folder, its flagged pairs, and every unit skipped with the reason. A later run into the same folder updates only the units it redid. In an `--all` run, a unit that fails is listed under `failed`, and the run goes on to the next unit.

On the 32 GB production GPU, RIFE takes about 0.5–3 s per unit. Reading the archive and packing take a few more seconds, and `--review` adds about 10 s.

## Environment

The tool needs Python 3.10 or newer with `torch`, `safetensors`, `numpy` and `Pillow`, and works on Windows and Linux. A CUDA GPU is strongly recommended; on the CPU it works but is slow. The repository's own Python does not need these packages; nothing else imports this tool.

On the owner's Windows machine, an existing conda environment already has everything (torch with CUDA, safetensors, Pillow, numpy). Use it read-only, and never install into it:

```text
H:\ai\envs\trellis2\python.exe -I -B tools/idle_inbetweens.py ...
```

On Linux, any virtual environment with a CUDA build of torch plus `safetensors numpy pillow` works.

## Model weights

The weights are `rife_v4.26.safetensors` (22,674,688 bytes, SHA-256 `151874592c877740e5db11522f4514df569eeafb0a0fcb2696f16e9e8d317c94`). They are not in Git. Download them from
`https://huggingface.co/Comfy-Org/frame_interpolation/resolve/main/frame_interpolation/rife_v4.26.safetensors`
and put the file at the default path, or pass `--weights`.

That file is Comfy-Org's repackage of the Practical-RIFE v4.26 model by hzwer (MIT). The tool also loads the original Practical-RIFE layout if it is converted to safetensors.

The network code, `tools/rife_ifnet.py`, follows Practical-RIFE and HolyWu's vs-rife port (both MIT; the notice is in the file). It does not use ComfyUI's GPL code. On smooth test images it matches the ComfyUI port to within 1e-6. On real units its loops match the prototype's to within 1.3% in premultiplied colour; the only differences are in near-transparent edge pixels.

## Which frames it reads

For each unit, the tool uses the idle clip that `content/unit_animation_manifest.json` plays:

- **148 units** have 8 paintings in `art/animation/source/poses/<unit>/idle-v2/hands-packing.json`. The tool uses them when the manifest idle has 8 frames.
- **62 fluid-batch units** list their idle frames in `art/animation/source/fluid/<unit>/reviewed_handoff.json`, under `clips.idle`.
- **20 units** have video idles, with 16–50 frames from the same handoff file. These frames carry `alpha_noise_cutoff`, which the tool applies. Seven of these units also have an 8-painting sheet, but the manifest plays the video, and so does the tool.
- **2 units** (`unit_neutral_sunscale_lanternmoths`, `unit_neutral_fenmirror_gallowshells`) still play the 8 paintings of the 2026-09-19 idle expansion.
  - Their fluid handoff keeps ("preserves") that idle rather than listing it.
  - `poses/<unit>/idle-v2/generation.json` names where the paintings were appended (`packing_recipe`, `packed_indices`), and the tool reads them from there.
  - All 16 frames match the game's current idle pixel for pixel.

Three fluid units mix scales within their idle frames:
- `unit_river_guard_veteran`
- `unit_embercourt_beaconline_writguard_veteran`
- `unit_mireclaw_fenbell_chainstalkers_veteran`

For these, the tool brings every frame to the largest scale, so frames are only ever reduced, and the figure keeps its size through the loop.

## Method

1. **Align.** Every frame is cut out the way `tools/pack_unit_pose_art` cuts it, then placed on one canvas with its ground anchor at the same point. The canvas sides are multiples of 128.
2. **Interpolate.** Each neighbouring pair, last to first included, runs through RIFE twice: once composited over black and once over white. From the two results:
   - alpha = 1 − (white result − black result), averaged over colour;
   - colour = black result / alpha;
   - alpha below 0.02 becomes clear.
3. **Check for smear.** For each in-between, the tool counts see-through pixels (alpha between 0.08 and 0.85) and divides by the larger count of the two frames around it. Above 1.6, the pair is smeared.
   - A smeared pair is redone with the coarse flow pass (`scale 0.5`: flow estimated from 1/32 of the size instead of 1/16), which follows large motions better.
   - The tool keeps whichever result smears less. If it still smears, the pair is flagged in `report.json` and `flagged.jpg`.
4. **Fit the cell.** Some idles, mostly video idles, reach within a pixel of their game cell's edge. A soft in-between edge there can spill a pixel past the cell once the packer shrinks the frame, and the packer refuses that. The tool simulates the packer's resize and clears only the in-between pixels that would land outside the cell. The accepted frames are never touched. `cell_clipped_px` in `report.json` counts the cleared pixels at source resolution; in the full roster run, only Bellwake Oars veteran needed this (two in-betweens, 43 and 79 pixels).
5. **Pack.** The game's packer turns the loop into cells at the unit's frame size, ground margin and scale.

In the first full roster run (2026-10-11), all 232 units took about 20 minutes and produced 1.9 GB of output. 33 units had a flagged pair: 19 painted units and 14 fluid units.
- Most only just crossed the threshold (ratio 1.6–1.9) and look fine.
- The worst, such as Gaugeplate Bailiffs (3.05), have a very large move between two paintings. There, the hammer goes from the hip to over the shoulder, and RIFE cross-fades a ghost hammer instead of moving it. Sunscale Lanternmoths shows the same with its wing beats: four pairs show a doubled wing.

Known limits:
- Big moves of fine detail can leave thin dark rims; this comes from the black/white matting.
- Painted detail that differs between two paintings morphs between them instead of popping, so painted units still "boil" a little, only more smoothly.

## Not yet in the game

Playing these loops in the game is a separate step that has not been built. It needs:

- `tools/integrate_unit_idle_poses.py` accepts exactly 8 idle frames; fluid units publish through `tools/publish_fluid_creature_animation.py`.
- The manifest's `pose_clips.idle` (`indices`, `frames`, `frame_msec`) must describe the longer loop. The idle area of each battle atlas grows about 3x.
- `art/overworld/creature_idle.json` reuses the battle idle frames, so the overworld idle strips must be repacked too.
- Changed idle pixels need re-registration in `docs/battle-unit-animation-acceptance.json`.
